# V5Pay + Tilda (bambumaker.com) — интеграция приёма платежей

Что это: маленький сервер на Node.js, который берёт на себя всё, что Тильда
сама сделать не может — создание платежа в V5Pay и приём callback-уведомлений
об оплате. Секретный ключ (`secretKey`) хранится только на этом сервере и
никогда не попадает в код на самой Тильде.

## Как это работает

1. Покупатель на bambumaker.com нажимает "Оплатить" (кнопка из
   `public/tilda-embed.html`, вставленная в блок Тильды).
2. Браузер покупателя обращается к вашему серверу: `POST /v5pay/create-payment`.
3. Сервер обращается к V5Pay, подписывает запрос, получает `checkoutUrl`.
4. Покупателя редиректит на `checkoutUrl` — там уже готовая платёжная форма
   от V5Pay, её верстать не нужно.
5. После оплаты V5Pay стучится на ваш сервер: `POST /v5pay/callback`.
6. Сервер проверяет подпись, один раз обрабатывает результат, отвечает
   `success`.

## Установка

```bash
npm install
cp .env.example .env
```

Заполните `.env`:
- `V5PAY_MERCHANT_NO`, `V5PAY_APP_KEY`, `V5PAY_SECRET_KEY` — из кабинета V5Pay
  (Merchant Admin Console → Приложения → создать приложение → дождаться
  одобрения). Сначала используйте **UAT**-ключи, не боевые.
- `PUBLIC_CALLBACK_URL` — публичный адрес вашего сервера + `/v5pay/callback`.
  Он должен быть доступен из интернета по HTTPS (это и нужно V5Pay указать
  как "Status Notification Address" в кабинете при создании приложения).
- `ALLOWED_ORIGINS` — домены сайта, с которых разрешено вызывать
  `/v5pay/create-payment` из браузера (CORS). По умолчанию bambumaker.com
  и www.bambumaker.com.

Запуск локально для проверки:
```bash
npm start
```

## Деплой (варианты, от простого к гибкому)

- **Render.com** — самый простой вариант для новичка: подключаете репозиторий,
  указываете `npm start`, вписываете переменные из `.env` в Environment,
  получаете бесплатный HTTPS-домен (`*.onrender.com`) — его и указываете как
  `PUBLIC_CALLBACK_URL`.
- **Railway.app** — аналогично, тоже просто и с бесплатным лимитом.
- **Обычный VPS** (если нужен свой домен/IP для production у V5Pay — они
  требуют IP сервера для боевого режима) — ставите Node.js 18+, `pm2` для
  автозапуска, Nginx + certbot для HTTPS.

## Тестирование

После того как заполнены UAT-ключи:

```bash
curl -X POST http://localhost:3000/v5pay/create-payment \
  -H "Content-Type: application/json" \
  -d '{
    "orderNo": "TEST001",
    "amount": "100.00",
    "email": "test@example.com",
    "productName": "Bambu Lab A1 mini",
    "productSku": "A1-MINI"
  }'
```

`orderNo` — только латинские буквы и цифры: с `-` или `_` V5Pay отвечает
`1002 incorrect format of orderNo` (проверено на UAT).

Должны получить в ответ `checkoutUrl`. Если платёжная ссылка не открывается —
в документации V5Pay сказано сменить `productType` на `TEST_BANK` для теста
(в текущем коде `productType` не передаётся специально, чтобы покупатель сам
выбирал способ оплаты на странице V5Pay — если для тестов нужно
принудительно открыть `TEST_BANK`, добавьте `productType: 'TEST_BANK'` в
`params` в `server.js`).

Приём заказов и выплаты также можно эмулировать в самом кабинете V5Pay:
"Инструменты" → "Simulate Refno" (для приёма) и "Order Status Simulation"
(для статусов).

## Открытые вопросы — уточнить у V5Pay/заказчицы до боевого запуска

1. **Код валюты для России.** В коде сейчас стоит `currency: 'USD'` как
   безопасное значение по умолчанию — в документации не нашлось прямого
   подтверждения, принимает ли российский кэшир `RUB` напрямую или всегда
   идёт конвертация из USD. Уточнить у специалиста V5Pay.
2. **Формат ответа на callback.** В документации сказано "синхронно
   ответить success", но точный ожидаемый формат (обычный текст `success`,
   или JSON вида `{"code":"1000"}`) не расписан явно — сейчас сервер
   отвечает простым текстом `success`. Если в логах/кабинете V5Pay будет
   видно, что уведомления всё равно повторяются — значит, нужно уточнить и
   поменять формат ответа.
3. **`productType`** — сейчас не передаётся (покупатель сам выбирает способ
   оплаты на странице V5Pay). Если нужно жёстко ограничить одним способом
   оплаты для российских карт — уточнить нужный код продукта.

## Структура проекта

```
server.js              — сам сервер (два эндпоинта)
lib/sign.js             — подпись/проверка подписи (сверено с примером из документации V5Pay)
lib/store.js             — защита от повторной обработки одного и того же callback
public/tilda-embed.html — код для вставки в блок Тильды
.env.example             — шаблон переменных окружения
data/                     — здесь хранится журнал обработанных платежей (создаётся автоматически)
```
